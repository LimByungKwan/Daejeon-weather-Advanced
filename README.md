# 대전 온도 기록 — 오늘의 진짜 정보판

대전 고정 좌표(36.3504, 127.3845)의 **지상 2m 현재 기온**을 Open-Meteo에서 조회합니다. 기상 모델 기반 값이며 관측소 실측값·하루 평균값으로 표시하지 않습니다.

## 완성된 앱과 실제 두 날짜 기록

| 실제 조회 날짜 · KST | 저장 기온 | 원천 시각 · KST | 실제 조회 시각 · KST |
|---|---:|---|---|
| 2026-10-06 | 12.7 °C | 22:30:00 | 22:39:21.780538 |
| 2026-10-07 | 14.8 °C | 22:30:00 | 22:40:45.923764 |

어제 대비: **14.8 − 12.7 = +2.1 °C**. 두 날 모두 같은 위치·API·기온 기준을 사용했습니다. 날짜나 조회 시각을 소급해서 바꾸지 않았습니다. 10월 1일 기록은 이번 최종 일별 기록에 섞지 않았고, 10월 5일 기록은 만들지 않았습니다.

원자료는 `data/2026-10-06-open-meteo.json`, `data/2026-10-07-open-meteo.json`에 있습니다. `records.json`은 같은 응답에서 만든 정규화 기록 정확히 2건을 포함합니다. `data.js`에도 같은 두 기록을 넣어 파일을 더블클릭해 열어도 초기값이 표시됩니다.

원천 URL:

https://api.open-meteo.com/v1/forecast?latitude=36.3504&longitude=127.3845&current=temperature_2m&timezone=Asia%2FSeoul&temperature_unit=celsius

## 실행과 배포

1. 압축을 풀고 `weather-board/index.html`을 더블클릭합니다. 현재 전달본의 기온·시각·두 날짜·변화량을 확인할 수 있습니다.
2. GitHub의 Public 저장소를 만들고 **weather-board 폴더 안의 파일과 하위 폴더 전체**를 저장소 최상위에 올립니다. ZIP 파일 자체나 weather-board 폴더 한 겹만 올리지 않습니다. 저장소 첫 화면에 index.html이 있어야 합니다.
3. Settings → Pages → Deploy from a branch → main / (root) → Save. 배포가 끝나면 HTTPS 사이트 주소를 시크릿 창에서 엽니다.

로컬 서버를 쓰려면 weather-board 폴더에서 `python -m http.server 8000`을 실행하고 http://localhost:8000 에 접속합니다. 로컬 파일에서 외부 API 요청이나 해시 확인이 제한되면 공개 사이트 또는 로컬 서버를 사용하세요.

결과물 URL은 실제 GitHub Pages 주소입니다. 소스 URL은 **최종 커밋의 전체 소스 주소**입니다.

`https://github.com/사용자/저장소/tree/최종커밋의40자리SHA`

`tree/main`이나 저장소 첫 화면은 C35의 고정 커밋 조건을 충족하지 않습니다. 이 전달본에는 실제 공개 결과물·소스 URL이 아직 없습니다. 모든 제출 URL은 로그인·인증·초대·비밀번호·OAuth·CAPTCHA 없이 열려야 합니다.

## 실제 날씨 화면

- 값·단위·출처 URL·원천 시각·조회 시각·Asia/Seoul을 함께 표시합니다.
- 일별 기록의 **대조 보기**에서 원응답과 정규화 행, 화면값을 확인합니다.
- 어제 대비 계산은 화면에 식으로 표시합니다. 소수점 한 자리로 표시하며 원래 숫자는 그대로 보존합니다.
- 조회 버튼은 실제 Open-Meteo 요청을 보냅니다. 같은 KST 날짜는 같은 ID·한 행을 최신 성공값으로 갱신합니다. 다음 날짜는 새 행을 만듭니다.
- 실패 시 마지막 정상값과 기존 기록을 유지하고 오래된 값 표시, 오류별 설명과 재시도 행동을 표시합니다.
- 자동 조회는 하지 않습니다. 처음에는 보관된 실제 응답을 표시하며, 원천 시각이 30분 넘게 지난 값은 오래된 보관값으로 설명합니다.
- 새 조회는 브라우저에 저장됩니다. 공개 기록을 바꾸려면 records.json을 내려받아 GitHub의 같은 파일을 교체해야 합니다. 이 전달본은 이미 실제 2건이 포함되어 있으므로 추가 조회 없이 두 날짜 대조가 가능합니다.
- 플랫폼 영수증을 발급받은 후 같은 날짜를 재조회·갱신하면 영수증 값과 달라질 수 있으므로 최종 제출 전에 다시 대조하세요.

## 공식 합성 장애 재생

장애 재생 탭은 공식 asset의 합성 지표만 사용합니다. 실제 기온과 구분하기 위해 값의 단위는 원본대로 **pt**입니다. 각 실패 버튼은 reset → D1-A → D1-B → 해당 실패 순서를 재생합니다.

| 실패 버튼 | 상태 | 남는 값 | 안내 |
|---|---|---:|---|
| 느린 응답 | stale / timeout | 105 pt | 잠시 기다린 뒤 재시도 |
| 401 거절 | stale / auth | 105 pt | 외부 원천 상태 확인 |
| 429 호출 제한 | stale / rate_limit | 105 pt | Retry-After 대기 |
| 오프라인 | stale / offline | 105 pt | 네트워크 확인 |
| 형식 변경 | stale / schema_error | 105 pt | 응답 형식 확인 |
| 다시 시도 · RECOVER-D2 | fresh / none | 120 pt | 다음 날짜 행 정확히 1건 추가 |

초기화는 합성 상태만 비웁니다. 실제 기록은 삭제하지 않습니다. 복구를 반복해도 다음 날짜 행은 중복되지 않습니다. 정상 D1-A → D1-B → D2 수동 재생도 가능합니다.

공식 자산은 assets/t04-real-information-board-public-v1/에 원본 그대로 포함합니다. **파일 해시 확인**으로 17개 원본의 SHA-256과 바이트 수를 검증합니다.

## 저장·검증 규칙

실제·합성 어댑터는 core.js의 같은 정규화 검증, 일별 갱신, 실패 보존 함수를 호출합니다. 고유키는 signal_id + record_date입니다. record_date는 실제 fetched_at을 Asia/Seoul로 변환해 생성하며 갱신해도 record ID와 최초 조회 시각을 보존합니다.

브라우저 저장은 단일 문서를 localStorage에 저장하며 지원 환경에서는 Web Locks로 탭 간 저장을 직렬화합니다. 공개 파일과 브라우저 기록을 합칠 때 같은 날짜는 더 늦은 성공 응답을 유지합니다. 이전 버전의 localStorage 키는 사용하지 않아 10월 1일 기록이 이번 제출본에 섞이지 않습니다.

파일 불러오기는 좌표·출처·시간대·단위·날짜·원자료와 저장값의 일치를 검사합니다. 불러오기 자체가 실제 조회 날짜를 증명하거나 플랫폼 영수증을 발급하는 것은 아닙니다.

개인 GPS·사용자 이름·계정·연락처·분석 추적은 사용하지 않습니다. 고정 도시 좌표만 조회합니다. 비상업용 공개 API이므로 비밀키·로그인 정보를 코드에 넣지 않습니다.

## 제출 전 별도로 남은 일

앱 구현과 서로 다른 실제 KST 날짜의 저장 기록 2건은 준비했습니다. 아래 외부 절차를 완료했다고 주장하지 않습니다.

- GitHub Pages 결과물 URL과 고정 커밋 소스 URL 생성 및 시크릿 창 접근 확인
- 과제 플랫폼의 **t04_day 봉인 영수증 정확히 2건** 확인
- 영수증 payload와 앱의 source_url / source_observed_at / normalized_value / unit 대조
- 제출문-초안.md의 본인 판단 문장을 확인하고 실제 URL과 함께 제출

첨부 public-contract.json은 영수증의 **server_created_at을 KST로 변환한 날짜가 서로 달라야 한다**고 규정합니다. 이 앱은 그 영수증을 생성하거나 과거 날짜로 발급하지 않습니다. 플랫폼 주소·발급 절차가 제공되지 않아 영수증 상태는 확인하지 못했습니다. 10월 6일 영수증이 없는 경우 지금 6일 payload를 전송한다고 서버의 생성 날짜가 6일이 되지는 않습니다. 해당 플랫폼에서 기존 영수증과 처리 방법을 확인해야 합니다.

원자료 대조 영역의 JSON은 확인용 payload이며 플랫폼 봉인 영수증이 아닙니다. `data/` 원자료와 과거 조회 시각을 바꾸지 마세요.
