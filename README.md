# 대전 날씨 정보판 고도화 · AI 인수인계 검증

기존 **대전 날씨 정보판**에 데이터 상태 진단 및 안내 기능을 추가하고, 서로 다른 AI 작업자가 이전 대화 전문 없이 **GitHub 저장소와 인수인계 문서**를 이용해 순차적으로 작업을 이어받을 수 있는지 검증한 프로젝트입니다.

> **검증 범위:** 작업자 X가 상태 진단 함수와 인수인계 문서를 남겼고, 작업자 Y가 이를 검토해 화면 연결과 오래된 데이터 판정·데이터 없음 안내를 개선했습니다. **Python/API로 두 모델을 자동 호출하는 기능은 아직 구현하지 않았습니다.**

## 주요 기능

- **`fresh`**: 날씨 데이터의 원천 시각을 기준으로 최신 상태를 판단합니다. 기본 기준은 30분입니다.
- **`stale`**: 오류 발생 또는 오래된 데이터를 사용자에게 알리고, 마지막 정상값을 유지합니다.
- **`empty`**: 유효한 데이터가 없을 때 마지막 정상값이 존재하는 것처럼 안내하지 않습니다.
- 마지막 정상 수집 시각을 상태 안내에 표시합니다.
- 기존 날씨 기록(`records.json`, `data/`)과 날짜별 비교·장애 재생 기능을 보존하는 방향으로 개선했습니다.

기존 기록은 Open-Meteo의 대전 고정 좌표(36.3504, 127.3845) 모델 기반 지상 2m 기온입니다. 실측 관측소의 직접 측정값은 아닙니다.

## 검사 실행 방법

GitHub 저장소의 **Actions → AI-A Diagnostic Tests → Run workflow → main**을 선택하면 다음 검사를 수행할 수 있습니다.

```bash
node --test tests/status-diagnostic.test.cjs
node --test tests/core.test.cjs tests/app.test.cjs
node --test tests/fixed-checks.test.cjs
```

워크플로에는 **`tests/browser.test.cjs`와 T10 Chromium 실측 검사가 포함되어 있지 않습니다.**

## 알려진 문제와 다음 작업

1. `tests/browser.test.cjs`는 작업자 Y 환경에서 429 응답의 “60초” 안내를 찾지 못해 실패했습니다. 기존 원본에서도 동일하게 발생했다고 보고되었으며 원인은 확인되지 않았습니다.
2. 조회하지 않은 보관 데이터가 30분 이내일 때, 배지의 “보관된 기록”과 진단 문구의 “최신”이 서로 다르게 보일 가능성이 남아 있습니다.
3. 실제 API 호출 및 실제 휴대폰 화면은 별도 검증이 필요합니다.
4. AI별 작업시간·요청/호출 수·고정 검사 실패 회차와 시작·종료 소스 버전 쌍을 다음 실행부터 직접 기록해 비교의 재현성을 높일 예정입니다.
5. Python/API를 통한 모델 간 자동 호출은 별도 후속 기능으로 고려하고 있습니다.
